## 条目

### BL-001 · Workspace 多 Dataset 同 Run 分析

| 字段 | 内容 |
|------|------|
| 提出日期 | 2026-09-07 |
| 来源 | 用户：Workspace 上传分析是否仅支持单文件 |
| 状态 | 已完成 |
| 优先级 | P1 |
| 关联现状 | 当前 `Conversation.dataset_id` 单绑定；Agent 工具仅加载一个 `df` / `data` 表 |

**问题**  
Workspace 可上传多个文件（多个 Dataset），但一次提问 / 一次 Agent Run 只能选中其中一个，无法在同一次分析中联合多表或多文件。

**期望（草案）**  
- 一次 Run 可绑定 ≥2 个 Dataset（或主表 + 辅表）。  
- Agent 能按场景做多表关联 / 对比（如 JOIN、并排汇总），或明确声明「仅预览多源后需用户选主表」的渐进方案。  
- UI：Dataset 多选或「主/辅」标记；Trace / Evidence 标明数据来源。

**候选方案（未锁定）**  
1. **多选 Dataset**：会话绑定 `dataset_ids[]`，沙箱注册多表名（如 `data` / `data_2`）或按文件名建表。  
2. **先合并再分析**：UI 提供「合并上传为单 Dataset」捷径（实现轻，能力弱）。  
3. **仅对比模式**：两次单源 Run + 对比报告（不改核心引擎）。

**非目标（暂）**  
跨 Workspace 数据联邦、任意跨库分布式查询。

**验收意向（立项时再写成 EARS）**  
- 用户可选两个已上传 CSV，一问完成涉及两表的汇总或对比。  
- 单 Dataset 路径行为不变。

**备注**  
用户当前权宜做法：分别跑两轮，或外部合并后再上传。

### BL-002 · Logic Canvas 节点全文与右侧详情联动

| 字段 | 内容 |
|------|------|
| 提出日期 | 2026-09-07 |
| 来源 | 用户：Logic Canvas 已完成小框文字展示不全；希望点击后右侧展示分析内容 |
| 状态 | 已完成 |
| 优先级 | P1 |
| 关联现状 | Canvas 节点 `summary` 截断展示；已有选中态与 Inspector「Node」Tab，但详情偏薄，未系统展示该步完整分析/输出 |

**问题**  
Logic Canvas 中已完成的各个节点卡片文案被截断，用户无法在框内读全；需要更顺畅的方式查看该步完整内容。

**期望（草案）**  
- 点击 Canvas 上某个已完成（或任意）节点后，**右侧 Inspector** 展示该节点对应的完整分析/输出（不仅是短 summary）。  
- 内容可包括：完整 `output_summary` / 步骤说明、关联 tool 结果摘要、必要时链到 Evidence。  
- 节点框内仍可保留截断标题；可选：悬停 Tip 显示更多一行（辅助，不替代右侧详情）。

**候选方案（未锁定）**  
1. 强化 Inspector「Node」Tab：选中节点时拉取 Trace step / tool_call 全文。  
2. 选中节点时自动切换到最相关 Tab（如有 evidence → Evidence，否则 Node）。  
3. 节点双击打开只读抽屉（若不愿占用 Inspector）。

**非目标（暂）**  
在 Canvas 小框内完整渲染长文、可编辑节点内容。

**验收意向（立项时再写成 EARS）**  
- 点击任一已完成节点，右侧可见明显长于卡片截断的完整文案或结构化详情。  
- 未选中时行为与现网一致。

**备注**  
与 BL-001 无关；属 Workspace 可观测性 / UX。

### BL-003 · Logic Canvas 节点可拖动

| 字段 | 内容 |
|------|------|
| 提出日期 | 2026-09-07 |
| 来源 | 用户：Logic Canvas 节点可拖动，增加页面可操作性 |
| 状态 | 已完成 |
| 优先级 | P2 |
| 关联现状 | 节点位置由 `flowModel` 按 Trace 自动排布；只读点击选中，不可拖拽改布局 |

**问题**  
Logic Canvas 节点固定网格布局，用户无法自行整理重叠/遮挡或按阅读习惯排布，可操作性偏弱。

**期望（草案）**  
- 支持拖动节点改变画布位置；拖动中边（edges）跟随更新。  
- 拖动不改变 Trace 逻辑顺序与执行语义，仅影响展示布局。  
- 可选：拖动后位置在当前页会话内保持；切换 Run 时仍按该 Run 的 Trace 重新布局（或记住用户布局——立项时再定）。

**候选方案（未锁定）**  
1. 在现有自研 Canvas 上增加 pointer drag（改 `FlowNodeModel.x/y`）。  
2. 引入轻量图编辑库（如 React Flow）统一拖拽/缩放（改动面更大）。  
3. 仅支持画布平移/缩放，节点仍自动排布（弱化版，不满足「拖节点」）。

**非目标（暂）**  
拖拽改边、增删节点、把 Canvas 变成可执行 Workflow 编辑器（与 V9 Workflow JSON 编辑不同）。

**验收意向（立项时再写成 EARS）**  
- 用户可拖动至少一个节点到新位置，边仍正确连接。  
- 点击选中 / Inspector 联动（含 BL-002）不被拖拽手势破坏（需区分 click vs drag）。

**备注**  
可与 BL-002 同批做「Canvas 交互增强」，或分 PR。
